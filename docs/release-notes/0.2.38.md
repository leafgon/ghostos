# ghostos 0.2.38

Date: 2026-11-05

Related issues:

- https://github.com/leafgon/ghostos/issues/112
- https://github.com/leafgon/ghostos/pull/135
- https://github.com/leafgon/hippocampus/issues/41

## Summary

This release combines Hippocampus runtime enablement from `origin/main` with
LEAFlisp numeric hardening from PR #135. Together, these changes make
Hippocampus execution production-ready in GhostOS and fix scientific-number
handling edge cases in LEAFlisp parsing/serialization paths.

## Changes Since v0.2.37

### Merged on `origin/main`

- Wired `leafelement:hippocampus` as a supported
  `side_effecting_action` runtime element (instead of blocked).
- Added strict adapter guardrails: intent validation, host-mediated execution,
  idempotency-aware behavior, retry/failure mapping, and fail-closed
  correlation checks.
- Added focused Hippocampus adapter tests and updated runtime classification
  inventory coverage.
- Updated library documentation for Hippocampus adapter guardrails and runtime
  expectations.

### Included from PR #135

- Hardened LEAFlisp scanner/runtime support for scientific literals (`e`/`E`
  notation), including direct runtime bundle paths used at execution.
- Fixed large-exponent magnitude handling so values like `1e+21`, `-1e+21`,
  `1e+28`, and `-1e+28` preserve expected runtime numeric value.
- Hardened decimal rendering logic beyond `toFixed` limits:
  - supports decimals `< 0`
  - supports decimals `> 100`
  - avoids range errors in these cases
- Hardened `tofixed` behavior with explicit runtime validation:
  - digits must be integer `[0, 100]`
  - value must be finite
- Added/updated browser-path regression tests for scientific numeric literals
  and inport round-tripping of large scientific numbers.
- Rebuilt publish artifacts and bumped package version metadata to `0.2.38`.

## Compatibility Notes

- `hippocampus` nodes now execute as wired side-effecting runtime actions;
  deployers should ensure host/runtime policy configuration is in place.
- LEAFlisp numeric behavior is stricter and safer:
  - invalid `tofixed` usage now throws `StdRuntimeError`
  - scientific literals and large-exponent round-trips preserve expected
    numeric value
- No public API surface expansion is introduced; this is primarily runtime
  correctness and enablement work.
